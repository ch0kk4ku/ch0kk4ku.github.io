# 配置修改速查

**改什么东西、打开哪个文件**——这张表就是答案。也可以用脚本一行命令打开：

```powershell
.\.tools\pnpm.cmd cfg                  # 按用途列出所有可改目标（不打开文件）
.\.tools\pnpm.cmd cfg 公告              # 打开「公告」相关文件
.\.tools\pnpm.cmd cfg 站点 友链          # 可一次给多个关键词
.\.tools\pnpm.cmd cfg content          # 打开日常内容：文章目录 + 关于我 + 留言板 + 友链页
.\.tools\pnpm.cmd cfg folder           # 直接打开整个 src/config 目录
.\.tools\pnpm.cmd cfg all              # 打开全部可编辑目标
.\.tools\pnpm.cmd cfg 公告 --editor=notepad   # 指定编辑器（默认自动探测 VS Code）
```

> 命令名是 **`cfg`**，不是 `config`——`pnpm config` 是 pnpm 自己的内置子命令，会被它截走。
> 也可以用 `pnpm open`（同义词），或直接 `node scripts/cfg.js 公告`。

> 脚本只负责**打开文件**，不修改任何内容。改完保存 → `git push` → Actions 自动构建上线。

## 五、改完怎么生效

```powershell
# 1. 本地预览（保存即热更新；需在普通终端里跑）
.\.tools\pnpm.cmd dev        # 打开 http://localhost:4321/

# 2. 发布
git add -A
git commit -m "chore(config): 调整了 xxx"
git push                     # Actions 自动构建，2-3 分钟后线上生效
```

> **改配置必须重启 dev 服务器**才会完全生效（部分配置如提醒框主题、字体需要重启）。

## 六、两处容易踩的坑

1. **改 `src/config/siteConfig.ts` 的标题，不要和首页横幅标题混淆**：
   - `siteConfig.title` → 浏览器标签页 + 导航栏左上角
   - `backgroundWallpaper.ts` 的 `homeText.title` → 首页大横幅上的那行字
2. **友链/配置都改完后，构建会更新 `src/constants/lqips.json`**（图片占位图数据），提交时记得一并 `git add`，否则工作区会一直有未提交改动。

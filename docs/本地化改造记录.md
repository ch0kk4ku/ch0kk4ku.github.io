# 本地化改造记录

本文件记录本项目**相对上游 [CuteLeaf/Firefly](https://github.com/CuteLeaf/Firefly) 做过的全部改动**，
目的是：① 让后续 `git merge origin/master` 时知道该复查哪些文件；② 说明每处改动的必要原因。

上游基线：`master` @ `91cbbef`（`package.json` 版本 6.16.8，Astro 7.3.2 + Svelte 5 + Tailwind 4）。

## B. base 路径适配

上游默认按**站点根路径**部署（`base: "/"`）。本站是 GitHub Pages **用户站**（仓库名
`ch0kk4ku.github.io`，发布在 `https://ch0kk4ku.github.io/`），本身就在根路径，因此这部分补丁
**对当前上线不是必需的**，保留它们的价值在于：

- 那些「未走主题 `url()` 工具」的硬编码路径在**语义上就是错的**，一旦你改用项目站
  （`https://<用户名>.github.io/<仓库名>/`）或调 `base`，它们会立刻暴露成 404；
- 修好之后你在两种形态之间切换只需改 `site_url` + `base` + `SITE_BASE` 三处，不必再逐个排查组件；
- `Astro.redirect("/404/")` 那 14 处属于明确的 bug（会跳到仓库外的站点根），与部署形态无关。

如果你只想保持根路径部署并且希望与上游尽可能一致，B2/B3 的补丁可以整体丢弃，
改用 `.tools/audit-base-links.mjs` 随时复查即可。

### B1. 构建配置

| 文件 | 改动 |

### B3. 「页面开关关闭 → 重定向 /404/」补 base

14 个页面在 `siteConfig.pages.*` 关闭时执行 `Astro.redirect("/404/")`，子路径下会跳到
`https://<用户名>.github.io/404/`（仓库外）。已全部改为 `Astro.redirect(url("/404/"))`，
并在缺少导入的文件补上 `import { url } from "@/utils/url-utils";`：

`bangumi`、`bilibili`、`booknav`、`dynamic/comments`、`dynamic/index`、`friends`、
`gallery/index`、`gallery/[album]`、`guestbook`、`myanimelist`、`projects/index`、
`projects/[slug]`、`sponsor`、`vndb`（共 14 文件，24 增 15 删）。

> 该迁移由 `.tools/fix-base-404-redirect.mjs` 完成，保留文件原有换行风格（仓库 `.gitattributes`
> 约定 `eol=lf`）。改动可用 `.tools/verify-patched-pages.mjs` 做字节级复核。

`generateOgImages` 关闭的原因：开启后每篇文章都要渲染一张 OG 大图，本地与 CI 构建时间显著变长；

所以归档文章不会出现在站点、RSS、搜索索引里。

### 已知环境注意事项

1. **dev server 需要一次提权运行**：受限沙箱下，Astro 配置加载阶段 Vite 8 的模块运行器加载
   CJS 包 `picomatch` 时报 `require is not defined`；以更宽权限运行同一条命令即可正常启动
   （实测 `[vite] connected.`，页面 200）。这属于运行环境限制，与代码无关，CI（GitHub Actions）不受影响。
2. **PowerShell 的 HTTP 客户端在本机不可用**（`Invoke-WebRequest` 报“基础连接已经关闭”），
   探活请用 `node -e "fetch(...)"`。
3. **构建结束经常显示 exit code 1**：Pagefind 会把关于 `<html>` 元素与中文分词的说明写到 stderr，
   PowerShell 据此判定失败。判断构建是否成功请看 `dist/` 是否刷新。

## E. 上游升级清单

`git merge origin/master` 之后，按下面顺序复查：

1. **冲突高发区**：`astro.config.mjs`（base 那一行）、`.github/workflows/deploy.yml`（SITE_BASE 那一段）、
   `src/config/*.ts`（你的站点信息）、`pnpm-workspace.yaml`（storeDir）。
2. **可能被上游改写而丢掉 base 补丁的文件**（B2 / B3 清单）：优先跑
   `node .tools/audit-base-links.mjs . "/"` 复验（将来若改成项目站子路径，则传入 `"/<仓库名>/"`），
   如果上游已自行支持 base，可删除对应补丁。
3. 重新验证：`type-check` → `check` → `build` → 链接体检 → 打开
   `http://127.0.0.1:4321/` 肉眼确认首页、文章页、RSS/Atom 页。
4. 若上游把默认 `base` 支持做完整了，建议直接删掉 B2/B3 的全部补丁，回到纯上游实现。

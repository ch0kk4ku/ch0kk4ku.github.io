# 本地运行与写作指南

这个仓库是你自己的博客站，基于 [Astro 7](https://astro.build/) + [Firefly 6.16.8](https://github.com/CuteLeaf/Firefly) 主题
（Firefly 本身是 [Fuwari](https://github.com/saicaca/fuwari) 的二次开发）。上游原始说明保留在 `README.md` 与 `AGENTS.md`。

## 1. 环境

| 项目 | 要求 | 本机现状 |
| --- | --- | --- |
| Node.js | `>= 22.23.0`（仓库 `package.json` 的 engines） | v24.14.0 ✅ |
| pnpm | 仓库 pin `pnpm@11.22.0` | 见下方说明 |
| 网络 | 首次安装依赖、构建时拉字体需要联网 | 通过本地代理 7897 已调通 |

### pnpm 为什么放在 `.tools/` 里

本机全局 `pnpm` 实际是 corepack 的转发脚本，它必须写 `%LOCALAPPDATA%\node\corepack` 才能装出
`pnpm@11.22.0`；而这个目录当前不可写，全局 npm 缓存目录同样不可写。为了不改动仓库的版本 pin、
也不动系统目录，把 pnpm 11.22.0 的发行版直接解包到了 `.tools/pnpm`，并提供一个包装脚本：

```powershell
# 在仓库根目录执行；.tools\pnpm.cmd 会自动把 node_modules\.bin 加进 PATH
.\.tools\pnpm.cmd install
.\.tools\pnpm.cmd dev
.\.tools\pnpm.cmd build
```

`node_modules\.bin` 里已经有 `astro`、`tsc` 等可执行文件，所以下面的命令也可以直接用：

```powershell
$env:PATH = "$PWD\node_modules\.bin;$env:PATH"
astro dev        # 等价于 pnpm dev
astro build      # 只跑 Astro 部分，不跑完整构建链
tsc --noEmit
```

> `.tools/`、`.pnpm-store/`、`.pnpm-cache/` 都已在 `.gitignore` 中，不会进版本库。
> `.pnpm-store` 放在工作区内（而不是系统盘）也是因为系统盘当前不可写，配置记录在 `pnpm-workspace.yaml` 的 `storeDir`。

### 网络与代理

依赖安装、构建时拉字体、以及 `pnpm build` 里获取 GitHub 卡片数据都用环境变量走代理：

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
$env:HTTP_PROXY  = 'http://127.0.0.1:7897'
```

代理没开时：依赖装不了；构建可能卡在字体下载（`cdn.jsdelivr.net`）。已经下载过的字体与
LQIP 数据会命中缓存，因此二次构建通常不再需要网络。

## 3. 日常维护：加文章、加友链都不需要手动改代码

### 3.1 导入一篇文章（含 Obsidian 笔记）

```powershell
# 最省事：只给文件路径，标题/日期/简介自动推导
.\.tools\pnpm.cmd import-post "D:\notes\我的笔记.md"

# 常用参数
.\.tools\pnpm.cmd import-post "D:\notes\wp.md" `
  --title="TSCTF 2026 Writeup" `
  --category=CTF `
  --tags=CTF,Writeup,Web安全 `
  --slug=tsctf-2026-writeup `
  --date=2026-10-15 `
  --dry-run      # 只预览，不落盘
```

它会自动做这些事（也是手动导入最容易出错的地方）：

| 自动处理 | 说明 |
| --- | --- |
| 丢弃源文件的 Obsidian front-matter | `tags:` / `created:` 之类换成博客需要的字段 |
| `>[!warning]` → `> [!warning]` | 标记与 `>` 之间缺空格会导致 callout 不被识别 |
| 修正 ` > ` 这类多余缩进的引用行 | 缩进会让引用块断裂，callout 退化成普通引用 |
| 删除 callout 标记与正文之间的空行 | 空行会把引用块切成两段 |
| 标题层级归位 | 笔记常从 `###` 起手，会统一提到 `h2`（文章标题本身是 h1）；代码块内的 `#` 注释不会被误改 |
| 代码块语言归一化 | `payload→sql`、`console→bash`、`text→plain` 等非标准写法 |
| 简介推导 | 取正文第一段有意义的话（跳过 `abstract`/`web` 这类结构标题） |

### 3.2 添加一条友链

```powershell
# 交互式：一路回车即可（只有站点名和站点地址是必填）
.\.tools\pnpm.cmd friend

# 或者一条命令给全参数（适合脚本化，不会发问）
.\.tools\pnpm.cmd friend --title="朋友的博客" --url="https://friend.com" `
  --img="https://friend.com/avatar.png" --desc="一句话介绍" `
  --tags="Blog,友链" --weight=10

.\.tools\pnpm.cmd friend:list          # 看现在有哪些
.\.tools\pnpm.cmd friend:remove        # 交互式移除
.\.tools\pnpm.cmd friend:remove --index=2   # 非交互式移除第 2 条
```

它只改动 `src/config/friendsConfig.ts` 里 `friendsConfig` 数组的内容，不会碰文件其它部分。

#### 一次真实的会话长这样

```text
D:\documents\blogs> .\.tools\pnpm.cmd friend
添加友链（直接回车表示留空 / 使用默认值，Ctrl+C 取消）

站点名（必填）: 朋友的博客
站点地址（必填，如 https://example.com）: https://friend.com
头像图片地址（完整 URL 或以 / 开头）（回车用 ）: https://friend.com/avatar.png
一句话描述（回车用 ）: 一个很会写博客的人
分类标签，逗号分隔（回车用 Blog）: Blog,友链
权重（数字越大越靠前）（回车用 10）: 10

已写入 src\config\friendsConfig.ts：
	{
		title: "朋友的博客",
		imgurl: "https://friend.com/avatar.png",
		desc: "一个很会写博客的人",
		siteurl: "https://friend.com",
		tags: ["Blog", "友链"],
		weight: 10,
		enabled: true,
	},
本地 `pnpm dev` 可直接看到效果，推送后线上生效。
```

参数对照（命令行模式同名）：

| 交互问题 | 命令行参数 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 站点名 | `--title` | ✅ | 卡片标题；重名会提示或直接拒绝 |
| 站点地址 | `--url` | ✅ | 必须以 `http://` 或 `https://` 开头 |
| 头像图片地址 | `--img` | — | 必须是完整 URL 或以 `/` 开头的站内路径，否则自动留空（显示首字母占位图） |
| 一句话描述 | `--desc` | — | 卡片副文案 |
| 分类标签 | `--tags` | — | 逗号分隔，默认 `Blog` |
| 权重 | `--weight` | — | 整数，默认 10，**数字越大排越前** |

#### 加完之后怎么看到效果

```powershell
# 本地看（可选）：另开一个终端启动 dev server，保存即热更新
.\.tools\pnpm.cmd dev        # 打开 http://localhost:4321/friends/

# 正式发布
git add -A
git commit -m "feat(friends): 添加 xxx 的友链"
git push
```

推送后 GitHub Actions 会自动构建并发布，约 2–3 分钟线上生效。

#### 常见问题

- **图片不显示**：`--img` 写了相对路径（如 `avatar.png`）会被自动留空，卡片只显示首字母；要显示图片就换成完整 URL。
- **顺序不对**：改 `--weight`，数字大的在前；想每次构建随机排序，把 `friendsConfig.ts` 顶部的 `friendsPageConfig.randomizeSort` 设为 `true`。
- **想临时下线某条友链**：把该条目的 `enabled` 改成 `false`（配置保留，下次改回来即可）。
- **友链页底部那张卡片**（站点名称/描述/链接/头像，带一键复制）是给来访者抄的，内容在 `src/content/spec/friends.mdx` 顶部的 `site` 对象里。

## 5. 写一篇新文章

在 `src/content/posts/` 下新建 `.md` 或 `.mdx` 文件，front-matter 常用字段：

```yaml
---
title: 文章标题
published: 2026-10-15          # 必填
updated: 2026-10-20            # 可选
description: 首页卡片上的一句话
image: ./cover.avif            # 可选封面；相对 md 文件的路径
tags: ["标签A", "标签B"]
category: 分类名
draft: false                   # true 只在开发模式可见
pinned: false                  # true 置顶首页
comment: true                  # 是否允许评论
password: ""                   # 填了就加密，需配 passwordHint
series: "系列名"                # 可选，系列文章
seriesOrder: 1
---

正文用 Markdown 写。
```

**写法手册就在本地**：`src/content/reference/` 里归档了主题自带的 13 篇演示文章，
覆盖提示框、代码组、Mermaid / PlantUML、KaTeX 公式、视频嵌入、文章加密、双链等全部扩展语法。
它们不在任何内容集合里，所以不会出现在站点上；要看效果就把对应文件复制回 `src/content/posts/`。

## 6. 部署到 GitHub Pages（当前配置）

当前按**用户站点**配置，发布地址就是 `https://ch0kk4ku.github.io/`（根路径）：

| 位置 | 当前值 |
| --- | --- |
| `src/config/siteConfig.ts` → `site_url` | `https://ch0kk4ku.github.io` |
| `astro.config.mjs` → `base` | `process.env.SITE_BASE ?? "/"` |
| `.github/workflows/deploy.yml` → `env.SITE_BASE` | `"/"` |

> `env:` 的值在 GitHub Actions 里**不做表达式求值**，所以 `SITE_BASE` 必须写死；改子路径时要三处同步改。

### 6.1 创建仓库并第一次推送

用户站点要求**仓库名必须等于 `<用户名>.github.io`**，这里就是 `ch0kk4ku.github.io`：

1. 在 GitHub 上新建仓库，名字填 `ch0kk4ku.github.io`。
   **不要**勾选 "Add a README / .gitignore / license"——保持空仓库，避免和本地历史打架。
2. 把本地 remote 指向新仓库并推送：

   ```powershell
   git remote set-url origin https://github.com/ch0kk4ku/ch0kk4ku.github.io.git
   git add -A
   git commit -m "chore: 初始化个人博客（Astro + Firefly）"
   git branch -M main        # 若沿用 master 则跳过这行，并同步改 deploy.yml 的 branches
   git push -u origin main
   ```

   推送时若提示需要认证，用 GitHub 的 Personal Access Token 或 `gh auth login`，
   **不要把 token 写进仓库里**。

3. 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**（只需设置一次）。
4. 之后每次 `git push` 到该分支，`.github/workflows/deploy.yml` 会自动构建并发布；
   也可以在 Actions 页面手动 `workflow_dispatch` 触发。
5. 站点地址：`https://ch0kk4ku.github.io/`。

> ⚠️ 仓库建好后，`git push` 需要能访问 github.com。本机目前直连不通，需要保持代理开启，
   并让 git 走代理（例如 `git -c http.proxy=http://127.0.0.1:7897 push`）。

### 6.2 以后想改成别的形态

| 场景 | 要改的地方（三处一起改） |
| --- | --- |
| 项目站 `https://<用户名>.github.io/<仓库名>/` | `site_url` 加 `/<仓库名>`；`astro.config.mjs` 的 base 默认值改 `"/<仓库名>/"`；`deploy.yml` 的 `SITE_BASE` 改 `"/<仓库名>/"` |
| 自定义域名 `blog.example.com` | `site_url` 改成该域名；base 保持 `"/"`；`SITE_BASE` 保持 `"/"`；并在 `public/CNAME` 写入域名（`public/` 下的文件会原样拷进 `dist/`） |
| Vercel / Cloudflare | 仓库自带 `vercel.json` 与 `wrangler.jsonc`，都按根路径部署，保持 base 为 `"/"` 即可 |

改完务必重跑一次构建并用体检脚本确认：`node .tools/audit-base-links.mjs . "/"`（子路径站则传 `"/<仓库名>/"`）。

## 7. 之后要启用评论

`src/config/commentConfig.ts` 当前是：

```ts
type: "none",
```

改成对应后端即可，例如 Giscus（纯前端、需要一个公开仓库并开启 Discussions）：

```ts
type: "giscus",
giscus: {
  repo: "<用户名>/<仓库名>",
  repoId: "<在 giscus.app 获取>",
  category: "General",
  categoryId: "<在 giscus.app 获取>",
  // 其余保持默认
},
```

Twikoo / Waline / Artalk / Disqus 的字段也都在同一文件里，注释写得很清楚（各后端需要自己的
服务端或 envId）。启用评论后，「留言板」页面（`pages.guestbook`）也会随之可用。

## 8. 上游同步

## 9. 遇到问题

- **`EADDRINUSE` / 端口 4321 被占用**：先确认是否已有另一个 dev 进程在跑
  （`Get-Process node` 查看，或直接访问 <http://127.0.0.1:4321/>），
  端口空闲后用 `--port 4322` 换一个端口即可。
- **`spawn EPERM` / 无法写 `%LOCALAPPDATA%`**：说明当前 shell 处于受限沙箱。本项目已验证：
  依赖安装与构建已完成，日常只需 `dev` / `build`，如再遇到同类拒绝，用一次提权运行同一条命令即可。
- **`pnpm dev` 报 `Unable to load your Astro config` / `require is not defined`**：同上，
  换用 `node node_modules\astro\astro.js dev` 或提权后再试。
- **构建卡在 fonts（`cdn.jsdelivr.net`）**：代理未开或瞬时故障，重试一次通常就好；
  已缓存的字体不会重复下载。
- **只有构建时出现 exit code 1**：PowerShell 会把 stderr 里的提示（Pagefind 关于
  `<html>` 元素与中文分词的说明）当成失败信号。判断构建是否成功请看 `dist/` 是否刷新。

## 1. 总览

**内容分两类，存放位置完全不同**：

| 类型 | 位置 | 怎么改 |
| --- | --- | --- |
| **文章** | `src/content/posts/*.md` | 编辑 Markdown 文件（front-matter + 正文） |
| **友链** | `src/config/friendsConfig.ts` | 用 `pnpm friend*` 命令 |
| **站点配置** | `src/config/*.ts`（23 个文件） | 直接编辑，用 `pnpm cfg` 定位 |
| **特殊页面正文** | `src/content/spec/`（关于我、留言板、友链页） | 编辑 Markdown |

**标签和分类没有独立配置文件**——它们完全由每篇文章 front-matter 里的 `tags` / `category` 自动汇总而成。所以"改标签"就是改那篇文章的 front-matter。

## 2. 写新文章

### 方式 A：导入写好的 Markdown（推荐）

```powershell
# 最简：只给文件路径，标题/日期/简介/slug 自动推导
.\.tools\pnpm.cmd import-post "D:\notes\我的笔记.md"

# 常用参数
.\.tools\pnpm.cmd import-post "D:\notes\wp.md" `
  --title="TSCTF 2026 Writeup" `
  --category=CTF `
  --tags=CTF,Writeup,Web安全 `
  --date=2026-10-15 `
  --dry-run          # 只预览，不落盘
```

它会自动处理这些**容易踩的坑**：

| 自动修正 | 原因 |
| --- | --- |
| 丢弃源文件的 Obsidian front-matter | 换成博客需要的字段 |
| `>[!warning]` → `> [!warning]` | 缺空格会导致 callout 不被识别 |
| 修正 ` > ` 这类多余缩进的引用行 | 缩进会让引用块断裂 |
| 删除 callout 标记与正文之间的空行 | 空行会把引用块切成两段 |
| 标题层级归位 | 笔记常从 `###` 起手，统一提到 h2（代码块内的 `#` 不动） |
| 代码块语言归一化 | `payload→sql`、`console→bash` 等 |
| 简介推导 | 取正文第一段有意义的话 |

### 方式 B：生成空白骨架

```powershell
.\.tools\pnpm.cmd new-post "文章标题"
```

## 3. 编辑已有文章

**文章就是普通 Markdown 文件，"编辑文章"= 用编辑器打开那个文件改。**

### 第一步：找到文章文件

```powershell
.\.tools\pnpm.cmd posts            # 列出所有文章（标题/日期/分类/标签/文件路径）
.\.tools\pnpm.cmd posts --tags     # 按标签汇总（有哪些标签、各几篇）
.\.tools\pnpm.cmd posts --cats     # 按分类汇总
.\.tools\pnpm.cmd posts --drafts   # 只看草稿
.\.tools\pnpm.cmd posts Writeup    # 按关键词过滤
.\.tools\pnpm.cmd posts --open     # 用编辑器打开所有文章
```

输出长这样：

```text
文章目录：src/content/posts（共 2 篇）

  MoeCTF 2026 Writeup
    文件: moectf-2026-writeup.md  (23.1 KB)
    发布: 2026-10-15
    分类: CTF
    标签: CTF, MoeCTF, Writeup, Web安全, 沙箱逃逸
```

### 第二步：打开并修改 front-matter

```powershell
.\.tools\pnpm.cmd cfg content      # 打开文章目录（或直接在编辑器里打开那个 .md）
```

文件顶部的 `---` 之间就是 front-matter：

```markdown
---
title: "MoeCTF 2026 Writeup"                                    ← 标题
published: 2026-10-15                                            ← 发布日期（必填）
description: "MoeCTF 2026 部分题目的解题记录：..."                  ← 首页卡片简介
tags: ["CTF", "MoeCTF", "Writeup", "Web安全", "沙箱逃逸"]          ← 标签（数组）
category: "CTF"                                                  ← 分类（单个字符串）
draft: false                                                     ← true = 不上线
---

正文从这里开始……
```

### 具体怎么改

| 想做什么 | 怎么改 |
| --- | --- |
| **加标签** | `tags: ["CTF", "Web安全"]` → 在数组里加一项：`["CTF", "Web安全", "Pwn"]` |
| **删标签** | 从数组里删掉那一项（注意别留下多余逗号） |
| **改标签名** | 直接改字符串。全站该标签下所有文章会一起变 |
| **换分类** | `category: "CTF"` → `category: "渗透测试"`（一篇文章只能有一个分类） |
| **改标题** | `title: "新标题"` |
| **改简介** | `description: "..."`（显示在首页卡片上） |
| **设草稿** | `draft: true`（只在本地 dev 可见，不会构建上线；改回 `false` 才发布） |
| **置顶** | 加一行 `pinned: true` |
| **加封面** | 加一行 `image: "./cover.avif"`（相对当前 md 的路径） |
| **改日期** | `published: 2026-10-20`（格式必须是 `YYYY-MM-DD`，否则构建失败） |
| **标记更新** | 加一行 `updated: 2026-10-25`（文章页会显示"上次编辑"） |

**改标签/分类不需要动任何其它文件**——`/tags/` 和 `/categories/` 页面会在下次构建时自动重新汇总。当前标签情况：

```text
CTF        2 篇        （两篇 Writeup 都有）
Web安全    2 篇
Writeup    2 篇
沙箱逃逸   1 篇        （只有 MoeCTF）
MoeCTF     1 篇
TSCTF      1 篇
```

> 小技巧：想让两篇 Writeup 在标签页里归到一起，就保证它们有共同的标签（现在已经是 `CTF`/`Writeup`/`Web安全`）。

### 第三步：发布

```powershell
git add -A
git commit -m "post: 更新《MoeCTF 2026 Writeup》的标签"
git push
```

## 4. 管理友链

```powershell
.\.tools\pnpm.cmd friend              # 交互式添加（只有站点名、站点地址必填）
.\.tools\pnpm.cmd friend:list         # 列出全部
.\.tools\pnpm.cmd friend:edit         # 交互式编辑（回车 = 保持原值）
.\.tools\pnpm.cmd friend:remove       # 移除
```

**不用交互也能一条命令搞定**：

```powershell
# 添加
.\.tools\pnpm.cmd friend --title="朋友的博客" --url="https://x.com" `
  --img="https://x.com/avatar.png" --desc="一句话" --tags="Blog,友链" --weight=10

# 编辑（只给要改的字段）
.\.tools\pnpm.cmd friend:edit --index=2 --title="新站名" --weight=30
.\.tools\pnpm.cmd friend:edit --index=2 --img="D:\pics\new.png"   # 换头像
.\.tools\pnpm.cmd friend:edit --index=2 --remove-image            # 清空头像
.\.tools\pnpm.cmd friend:edit --index=2 --disable                 # 临时下线
.\.tools\pnpm.cmd friend:edit --index=2 --enable                  # 重新上线
```

**头像会被自动处理**：本地文件或远程 URL 都会**居中裁成正方形**、存进 `public/friends/`、配置里写成站内路径（顺便绕开博客园等图床的防盗链 403）。改标题时头像文件会自动跟着改名。

## 5. 改站点配置

```powershell
.\.tools\pnpm.cmd cfg              # 列出所有可改目标
.\.tools\pnpm.cmd cfg 公告          # 打开公告配置
.\.tools\pnpm.cmd cfg 站点 友链      # 一次给多个关键词
.\.tools\pnpm.cmd cfg folder       # 打开整个 src/config 目录
```

常用位置（完整表见 [配置修改速查](./配置修改速查.md)）：

| 想改什么 | 文件 |
| --- | --- |
| 站点标题/副标题/描述/关键词/URL | `src/config/siteConfig.ts` |
| 主题色、页宽、每页文章数 | `src/config/siteConfig.ts` |
| **页面开关** | `src/config/siteConfig.ts` 顶部 `pages` |
| 昵称、签名、头像、社交链接 | `src/config/profileConfig.ts` |
| **公告**文案与链接 | `src/config/announcementConfig.ts` |
| 壁纸、首页大标题/副标题 | `src/config/backgroundWallpaper.ts` |
| 导航栏菜单 | `src/config/navBarConfig.ts` |
| 侧边栏组件与顺序 | `src/config/sidebarConfig.ts` |
| 音乐播放器 | `src/config/musicConfig.ts` |
| 关于我 / 留言板 / 友链页正文 | `src/content/spec/` |

**注意**：`siteConfig.title` 是**浏览器标签页 + 导航栏**，首页横幅那行大字在 `backgroundWallpaper.ts` 的 `homeText.title`，两者不是一个东西。

## 6. 开关页面

在 `src/config/siteConfig.ts` 顶部的 `pages` 里改 `true` / `false`：

| 页面 | 当前状态 |
| --- | --- |
| 友链 `friends` | ✅ 开 |
| 留言板 `guestbook` | ❌ 关 |
| 动态 `dynamic` | ❌ 关 |
| 项目 `projects` | ❌ 关 |
| 相册 `gallery` | ❌ 关 |
| 书签导航 `booknav` | ❌ 关 |
| 追番 `bilibili` / `bangumi` / `vndb` / `mal` | ❌ 关 |
| 打赏 `sponsor` | ❌ 关 |

**导航栏会自动重排**（在 `src/utils/nav-menu-utils.ts` 里实现）：

- 父菜单的子项**全部关闭** → 该父菜单整个消失
- 父菜单**只剩 1 个子项** → 该子项被提升为一级菜单
- 还有多个子项 → 保留下拉

例如：关掉「留言」后，「社交」下拉消失、**友链自动升为一级菜单**（现在就是这个状态）。

## 7. 本地预览与发布

```powershell
# 1. 本地预览（保存即热更新）
.\.tools\pnpm.cmd dev          # 打开 http://localhost:4321/

# 2. 发布（推完 2-3 分钟自动上线）
git add -A
git commit -m "post: xxx"
git push
```

**提交前自检**（可选，但推荐）：

```powershell
.\.tools\pnpm.cmd check         # Astro 诊断
.\.tools\pnpm.cmd type-check    # TypeScript 检查
```

**部署是全自动的**：推送到 `main` 后 GitHub Actions 会依次跑 GitHub 卡片数据 → LQIP → Astro 构建 → 字体子集 → 搜索索引 → 发布 Pages。你不用碰任何部署配置。

## 9. 五个必须知道的坑

1. **`published` 是必填的**，格式必须 `YYYY-MM-DD`，漏了或写错会让构建失败。想"先存着不发"用 `draft: true`。
2. **`git add -A` 要带上 `src/constants/lqips.json`**——每次新增/更换图片，构建都会更新这个图片占位图数据文件。不带的话工作区会一直显示未提交改动。
3. **改 tags / category 后不需要动别的文件**，但**必须重新构建**（`pnpm dev` 会自动重建；线上靠 `git push`）。
4. **`siteConfig.title` ≠ 首页横幅标题**（见第 5 节）。
5. **文章文件建议用英文/拼音命名**（文件名会成为 URL 的一部分）；想用中文，就在 front-matter 里指定 `slug: my-post`。
